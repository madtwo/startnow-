# StartNow · 模型接口并发与 429 排队策略（Patch 6）

## 背景与边界

`OPTIMIZATION-BACKLOG.md` 的 P1-5 要求减少同卡多同伴并行回复时的 API 突发。只修改共享 `src/lib/llm.ts` 调用路径和新增的 `src/lib/providerConcurrency.ts`，**不修改 `room/*`、卡型门禁、完成归属、Q01 的冻结哈希或人设/记忆内容**。

## 正式行为

- 用经过尾斜杠规范化的 **配置 Base URL** 区分不同的模型接口；每个接口最多 **2** 个正在进行的请求。不同服务商/订阅接口独立计算；不保存 Key、消息或系统提示词。
- 请求从拿到名额才开始执行网络回调；对流式响应，名额一直占用到 SSE 读完、报错或取消；JSON 则到正文读取完。连接测试 `testConnection()` 同样占名额。
- 超过上限按先来先服务（FIFO）等候。排队时 `AbortSignal` 取消或超时会移出队列，**不发网络请求**；正在执行的请求由原有 `fetch`/`AbortSignal` 行为处理。任何成功、失败都应释放名额。
- 服务器返回 **429** 时，沿用 `Retry-After` 和 `LlmError('rate')`，且**拒绝同批已经排队但尚未发出的请求**。这些请求接收不含上游错误正文的通用错误（防止不同会话间传播服务商详情）。正在进行的请求不会被强制取消；不自动付费重试，不在 429 上立刻切备用模型。后续是否重试由现有调用端退避策略决定。
- 不缩短输入上下文、记忆、输出 Token；不改变真实模型选择及账单。未发送的排队请求不会产生 API 流量。但现有业务层的“尝试计数”是在调用 `streamChat` 前记录的，与真正的网络请求数并非完全等价，未来应在 Token/延迟面板中分别统计。
- 限制仅针对**本页 JavaScript 执行上下文**，不等于跨浏览器标签页、跨终端或跨服务器的全局限流。生产服务端仍应配置自己的配额保护。不是流式 UI 的实现；当前 UI 仍可能在生成完后显示整条论坛回复。

```sh
npm run test:provider-concurrency

```
