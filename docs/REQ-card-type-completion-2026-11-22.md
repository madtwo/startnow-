# 需求包：卡型与完成链路收口（2026-11-22）

## 1. 触发案例

截图中的卡片是一张炫耀卡（右上角「做到了」），却进入了：

`用这条作为下一步 → 贴到便签 → 我做到了 → 同伴完成回应`

最终出现：

- 玩家完成句：`做到了：呃……最近的状态的事啊。我也刚来，不太会接，但我在听。`
- 沈默回应：`「不太会接」你做了。我病理第三章还放在那儿，今天就不催你继续了。`

这不是单句文案问题，是四层状态机同时失守。

## 2. 根因

1. **卡型没有门禁**
   - `CardDetail` 对任何自己的卡都显示「用这条作为下一步」。
   - `adoptCommentAdvice` / `acceptAdvice` / `completeCard` 没有拒绝 brag/life。
2. **“下一步”没有可执行性校验**
   - `adoptCommentAdvice` 只检查来源、长度、安全，不检查这句话是不是动作。
   - 纯回应「我也刚来，不太会接」可以被收成 note。
3. **mock 回复没有按卡型分流**
   - 低亲密度首评一律使用 `TENTATIVE`，炫耀卡也被问「你想从哪讲起」。
4. **完成锚点盲信 note 文本**
   - `completeCard` 用 note 原文拼「做到了：…」。
   - 完成回应 fallback 再从这句话里抽锚点，抽出「不太会接」。

## 3. 需求

### R1 卡型矩阵

| 卡型 | 评论 | 给下一步 / 采用下一步 | 贴便签 / 我做到了 |
| --- | --- | --- | --- |
| worry | 允许 | 允许，但建议必须可执行 | 允许 |
| goal / progress | 允许 | 允许，但建议必须可执行 | 允许 |
| brag（含炫耀结果卡） | 允许，只祝贺 | **禁止** | **禁止** |
| life | 允许，只接细节/回应 | **禁止** | **禁止** |
| guide | 不放普通评论/建议 | 禁止 | 禁止 |

### R2 可采用的建议必须可执行

采用一条 persona 评论作为下一步时，必须满足至少一项：

- 评论带有 `actionId`；或
- 文本通过 `looksLikeActionableAdvice`（包含动作词 + 建议/指令结构）。

以下必须拒绝：

- 「我也刚来，不太会接，但我在听。」
- 「你先说，我不急。」
- 「你想从哪讲起？」
- 纯安慰、纯提问、纯身份声明。

拒绝时给玩家可见提示，不写 note。

### R3 卡型对应的回复约束

- brag：第一条同伴回复必须是明确祝贺；不得出现「我也刚来」「你想从哪讲起」「最近的状态」等试探句。
- life：只接具体细节，不给下一步。
- worry/goal：可以问澄清，也可以给一步；但不能把纯回应当作可执行建议。

### R4 完成锚点必须来自动作

- `completeCard` 只接受：
  - 有 `actionId` 的 note；或
  - note 文本可执行。
- 不合格 note 不允许完成，返回原卡并给提示。
- 旧存档里的坏 note：完成回应最多退回「刚才那件小事」，不得从「不太会接」这类文本抽锚点。

### R5 mock 与真实模型同一套卡型规则

- mock 分支按 `card.kind` 分流，不能绕过 brag/life 规则。
- 真实模型路径对 brag 卡增加“明确祝贺”门禁；不通过时走祝贺 fallback，不发布试探句。

## 4. 测试矩阵

| 编号 | 输入 | 期望 |
| --- | --- | --- |
| C1 | brag 卡 + 纯回应评论 | UI 无「用这条作为下一步」；`adoptCommentAdvice` 返回 error；`completeCard` 不改变卡 |
| C2 | brag 卡 + 低亲密度首评（mock） | 回复含明确祝贺，不含「刚来/你想从哪讲起」 |
| C3 | life 卡 + 任何建议 | 不进入 note / 完成链路 |
| C4 | worry 卡 + 纯回应评论 | 采用失败，提示“这条更像回应” |
| C5 | worry 卡 + 可执行建议 | 可以贴便签并完成 |
| C6 | 坏 note「我也刚来，不太会接」 | `completeCard` 返回原卡；完成回应不出现「不太会接」 |
| C7 | 截图同款完整链路 | 不允许从 brag 卡走到「我做到了」；不产生「不太会接」回应 |

## 5. 验收命令

```sh
npm run test:baseline
npm run test:v4
npm run build
node --test tests/forum-card-type-completion.test.cjs
```

浏览器验收（独立无头 profile）：

- 发一张炫耀卡，确认没有「给下一步 / 用这条作为下一步 / 我做到了」。
- 发一张烦恼卡，纯回应不可采用；可执行建议可以贴便签并完成。
- 公开站重新发布后，用新访客身份复验。

## 6. 为什么之前没发现

- 既有测试多是单元/合成：分别测“评论生成”“完成回应”，没有把 **卡型 + 纯回应 + 采用 + 完成** 串成一条。
- 浏览器 happy path 用的是 worry 卡，没有用 brag 卡走完“采用 → 完成”。
- mock 分支在 `persona.intimacy < 22` 时直接走 `TENTATIVE`，绕过了 brag 提示词规则；测试没有断言“brag 首评必须是祝贺”。
- `adoptCommentAdvice` 的历史测试只覆盖安全/来源，没有覆盖“这句话是不是动作”。
- 没有一条“非动作 note 不能完成”的不变量测试。

## 7. 不做

- 不删除卡片评论、不改变正常 worry/goal 的建议链路。
- 不把 brag 卡改成可执行卡；炫耀卡只收回应与祝贺。
- 不靠放宽全局正则解决单条案例。
- 不以“AI 文案不好”掩盖状态机错误。
