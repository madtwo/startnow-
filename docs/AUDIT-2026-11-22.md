## 本轮新发现并修复

### 1. 便签抽屉不随导航/ESC 关闭（P1）

现象：打开便签后切到日程、历史、群聊、我的，抽屉一直盖在右侧；手机上整屏遮挡。Escape 也不关。

修复：`view/homeTab` 变化时自动关闭；Escape 关闭。

### 2. 非动作建议仍显示“贴到便签”（P1）

现象：模型/旧数据给出一句纯回应（如“我也刚来，不太会接”），CardDetail 和 StepBoard 仍显示“贴到便签”；点击后 `acceptAdvice` 静默拒绝，看起来像按钮坏了。

修复：CardDetail / StepBoard 只有在 `actionId`、material 或 `isActionableStepText` 通过时才显示可用按钮；否则显示“这条更像回应，先换一条具体建议”。

### 3. 坏 note 仍能在首页完成（P1）

现象：CardDetail 已隐藏坏 note 的完成按钮，但 StepBoard 的 `noted` 焦点仍显示“我做到了”；点击后 `completeCard` 拒绝，没有反馈。

修复：StepBoard 用同一套 `noteActionable` 门禁；坏 note 不显示完成按钮，显示提示。

### 4. 旧 brag/life 数据泄漏到首页/便签/详情（P1）

现象：旧存档中 brag/life 卡可能带 note/advice；虽然新流程禁止，但 StepBoard、NoteDrawer、CardDetail 仍可能显示旧完成/建议。

修复：三个入口统一加 `canUseNextStep`；brag/life/guide 的旧 note/advice 不再进入下一步、便签抽屉或完成按钮。

### 5. 发卡后浏览器返回重新打开空白编辑页（P1）

现象：发卡后从首页按浏览器返回，会回到已经提交过的“放一张卡”编辑页。

修复：发卡提交后把历史当前项 `replaceState` 成首页，不再保留编辑页历史。

### 6. 生活卡 mock 首评仍在问“你想从哪讲起”（P1）

现象：brag 已修，但 life 卡在低亲密度首评仍走 `TENTATIVE`，对“食堂鸡腿饭很好吃”也问“最近的状态”。

修复：mock life 使用生活回应句，不再问身份/状态；新增回归。

### 7. 炫耀/生活卡详情仍有“直接要一个下一步”（P1，真实模型审计发现）

现象：CardDetail 的“直接要一个下一步”入口没有走 `nextStepAllowed`，brag/life 卡仍能请求下一步。

修复：该入口也加 `nextStepAllowed`；brag/life 只剩评论/点赞。

### 8. 炫耀卡两个同伴回复同一句祝贺（P2，真实模型审计发现）

现象：真实模型输出被 brag 门禁拒绝后，两个同伴 fallback 得到完全相同的祝贺句。

修复：brag fallback 改用 persona-specific `peerReactionFallback`，不再共用同一句；新增 4 人不同句回归。

## 真实模型审计

使用 OpenCode Go / DeepSeek V4.1 Flash，经本地 `/api/opencode-go` 代理，Key 只存在独立浏览器 profile，未进入聊天、日志或仓库。

| 路径 | 实际结果 |
| --- | --- |
| 烦恼卡 | 回复贴题；“研究意义”下一步贴题；贴便签、完成后有 grounded 完成回应 |
| 炫耀卡 | 回复明确祝贺；详情无下一步/采用/完成（本轮修复后） |
| 生活卡 | 回复“鸡腿饭”具体细节；详情无下一步（本轮修复后） |
| 目标卡 | 回复围绕“文献综述框架/周三” |
| 自动拆解 | 生成 5 步，总约 140 分钟/3 天；重新拆解清空答案并保留目标 |
| 帮助同伴 | 给魏霓三个小标题建议，魏霓接受并回复“能落地” |
| 调用量 | 约 12 次；无模型 Key 泄漏 |

审计过程中出现过一次 Puppeteer 页面上下文 `SecurityError: localStorage`，未影响业务流程；没有把它当成产品通过证据。

## 为什么之前漏掉

- 旧测试测的是单点函数和 happy path，没有把“旧数据 + 卡型 + 三个 UI 入口”串起来。
- 采用了“后端拒绝”就认为 UI 安全，没有验证按钮是否仍可点、点了是否静默无反应。
- 浏览器历史只测了详情/日程，没有测“发卡提交”这种 replace 场景。
- brag 修复后没有把同一类问题扩展到 life。
- 没有把“首页 StepBoard / 便签抽屉 / 详情”当成同一套不变量检查。
